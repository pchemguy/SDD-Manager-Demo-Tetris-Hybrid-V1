## Delivered capabilities and honest deferrals

Milestone 1.1 delivers a playable falling-block loop in the browser:

- **Pure rules and geometry (`C1`–`C3`)**: Standard 10×20 visible playfield (`y = 0..19`, `x = 0..9`), all seven tetromino spawn orientations at `x = 3, y = 0` (`y = 1` for `I`), deterministic seven-bag queue and one-piece preview, horizontal movement (`move-left`, `move-right`), soft drop (`soft-drop`), chronological elapsed-time advancement (`tick`), `500 ms` grounded lock delay with airborne reset, simultaneous 1–4 full-row removal, next-piece spawn, and blocked-spawn `game-over` (`top-out`).
- **Playable browser application (`C4`–`C7`)**: Native button and keyboard `start`/`restart` (`Enter`), native `ArrowLeft`/`KeyA`, `ArrowRight`/`KeyD`, and `ArrowDown`/`KeyS` input routing with narrow `preventDefault()` on handled gameplay keys and editable-target bypass, `requestAnimationFrame` delta loop clamped to `[0, 100] ms`, Canvas 2D board and next-piece preview rendering with non-background pixel verification, and DOM status/lifecycle overlays (`ready`, `playing`, `game-over`).
- **Explicit deferrals to subsequent Phase 1 milestones** (per PLAN and TASKS):

    - Hold queue swaps (`Milestone 1.3`, `T-012`), ghost landing piece rendering (`Milestone 1.3`, `T-013`), and immediate-lock hard drop (`Milestone 1.3`, `T-014`)
    - Custom `150 ms` DAS / `50 ms` ARR held-key auto-repeat (`Milestone 1.4`, `T-016`), responsive layout/DPI resize polish (`Milestone 1.4`, `T-017`), and full cross-engine error/isolation and static delivery verification (`Milestone 1.4`, `T-018`–`T-019`)

## Implementation code review (separate from test execution)

A read-only implementation code review was performed across all Milestone 1.1 source, test, and configuration files against ARCHITECTURE, DECOMPOSITION, SPEC (`R01`–`R05`, `R07`, `R09`–`R12`), PLAN, and layout:

- **Component boundaries and dependency direction (`C1`–`C7`)**:
    - Inspected `src/game/types.ts`, `src/game/pieces.ts`, `src/game/board.ts`, `src/game/bag.ts`, `src/game/state.ts`, and `src/game/engine.ts`. Confirmed zero DOM, `window`, `document`, Canvas, or timer imports inside `src/game/`.
    - Confirmed `src/browser/keyboard.ts` (`C4`) is a pure translator with no DOM or engine state mutations, `src/browser/view.ts` (`C6`) renders solely from `GameSnapshot` and never mutates engine state, `src/browser/controller.ts` (`C5`) coordinates events and `requestAnimationFrame` exclusively through `GameEngine.dispatch()` and `GameView.render()`, and `src/app.ts` / `src/main.ts` (`C7`) own root container lookup and bootstrapping.
- **Contract and invariant fidelity**:
    - **`R01` / `R07` (`pieces.ts`, `board.ts`)**: All seven tetromino cell tables match SPEC `R01`. `getRotationCandidateOffsets()` returns the exact 5-offset horizontal kick order `(0,0), (-1,0), (+1,0), (-2,0), (+2,0)` (and `[(0,0)]` for `O`). `projectLandingY()` steps downward from `piece.y` until `canPlacePiece` fails, guaranteeing maximal valid non-penetrating landing projection. `lockPieceAndClearLines()` clones the board, writes occupied cells, removes full rows simultaneously, and prepends empty top rows while preserving relative order of surviving rows.
    - **`R03` (`bag.ts`)**: `shuffleBag()` performs descending Fisher–Yates from `i = 6` down to `1` using validated `[0, 1)` samples; `validateSample()` throws `RangeError` before any queue mutation if a sample is `NaN`, infinite, `< 0`, or `>= 1`.
    - **`R02` / `R04` / `R05` / `R11` (`state.ts`, `engine.ts`)**: `validateSeed()` rejects malformed boards, invalid piece coordinates/types/orientations, negative timers, or invalid queue state with `RangeError` before modifying engine state. `validateAction()` rejects malformed actions or non-finite/negative `elapsedMs` with `TypeError` before modifying engine state. `advanceTime()` processes chronological sub-steps (`min(remaining, timeToGravity, timeToLock)`), resolving lock expiry at `500 ms` before coinciding gravity ticks, locking, clearing 1–4 rows simultaneously, resetting `canHold = true`, spawning the next piece, and transitioning to `game-over` while preserving the blocking active piece when the spawn footprint collides.
    - **`R09` / `R10` / `R12` (`keyboard.ts`, `view.ts`, `controller.ts`, `app.ts`)**: `isEditableEventTarget()` guards `INPUT`, `TEXTAREA`, `SELECT`, and `contentEditable` elements; `KeyR` with `ctrlKey`/`metaKey`/`altKey` is ignored so browser reload shortcuts are never intercepted; `mountApp()` throws a descriptive `Error` when the root container is missing or lacks Canvas 2D support; production build outputs only `dist/index.html` and `dist/assets/*` without any `tests/browser/harness/*` files.
